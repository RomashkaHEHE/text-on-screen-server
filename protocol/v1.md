# Protocol v1

All endpoints and WebSocket messages are versioned under `/api/v1`. A client MUST reject a server protocol version it does not understand. The server advertises `minimumClientVersion` and `minimumProtocolVersion` in the version endpoint and in the WebSocket `hello` message.

## Session creation

`POST /api/v1/sessions`

Request:

```json
{ "title": "optional room title" }
```

Response `201`:

```json
{
  "sessionId": "K7d3mP2q",
  "editorToken": "...",
  "viewerToken": "...",
  "editorUrl": "https://example.com/editor/?session=K7d3mP2q&token=...",
  "viewerUrl": "wss://example.com/api/v1/sessions/K7d3mP2q?token=..."
}
```

Tokens are random bearer secrets. The editor token can write; the viewer token is read-only. Tokens are never logged.

## WebSocket

Connect to `/api/v1/sessions/{sessionId}?token={token}`. The server sends:

```json
{ "type": "hello", "protocolVersion": 1, "sessionId": "K7d3mP2q", "role": "editor" }
{ "type": "sync", "update": "base64-yjs-update" }
```

The Yjs document contains:

- `text` (`Y.Text`) — the visible text.
- `settings` (`Y.Map`) — `color`, `opacity`, `fontFamily`, `fontSize`, `outline`, `background`, `x`, `y`, and `visible`.

A client sends a changed Yjs update:

```json
{ "type": "sync", "update": "base64-yjs-update" }
```

The server validates a 256 KiB message limit, applies the update, and broadcasts it to all connected clients. Viewers may send no updates. Unknown message types are ignored with an `error` envelope. Updates are idempotent, so reconnecting clients can safely resend pending updates.

Optional presence:

```json
{ "type": "awareness", "state": { "clientId": "...", "name": "..." } }
```

Presence is ephemeral and is not persisted.

## HTTP version and release endpoints

- `GET /api/v1/version` returns the current protocol and app compatibility metadata.
- `GET /api/v1/releases/latest` returns the current semver and installer URL. A client compares semver locally.
- `GET /api/v1/releases/{version}/...` serves immutable release files.

If `minimumClientVersion` is newer than the app version, the app must block starting a broadcast and show an update-required message. The server rejects sessions from clients declaring an older protocol in their `hello` query in a later protocol revision.
